# Run Mile

สกอร์บอร์ดวิ่งแบบเรียลไทม์ มี 1 หน้า (ดูอย่างเดียว ไม่มีหน้าแอดมิน):

- **`/run-view.html`** — มุมมอง "เส้นทางวิ่ง" — ทุกทีมวิ่งอยู่บนเส้นทางจริงเดียวกันจากกรุงเทพฯ (TDFB HQ) ไปเชียงราย โดยตำแหน่งบนแผนที่อ้างอิงระยะทางถนนจริง (Highway 1 / พหลโยธิน) อัปเดตอัตโนมัติทุก ~3 วินาที พร้อมฟีดกิจกรรมล่าสุด

หน้านี้คุยกับ Express server ตัวเดียวกัน (`server.js`) ซึ่ง**ไม่มีการกรอกข้อมูลผ่านแอปเลย** — กม. สะสมของแต่ละทีมมาจาก Google Sheet ที่ทีมงานตรวจสอบหลักฐาน (รูปวิ่ง) แล้วสรุปคะแนนไว้ในแท็บที่ publish เป็น CSV, server จะดึงมาทุก ~90 วินาที (`SHEET_POLL_MS`) แล้วเก็บไว้ใน memory ให้หน้าเว็บอ่านต่อ — ทุกคนที่เปิดลิงก์ ไม่ว่าจะเป็นคนละเครื่องคนละที่ ก็เห็นข้อมูลชุดเดียวกันเสมอ ดูรายละเอียดขั้นตอน Sheet ทั้งหมด (โครงสร้างแท็บ, สูตร, ฟอร์ม) ในหัวข้อ "ที่มาของข้อมูล" ด้านล่าง

รองรับจอมือถือ — layout จะสลับเป็นแนวตั้งเองอัตโนมัติเมื่อจอแคบ

### มุมมองเส้นทางวิ่ง (`/run-view.html`)

ตำแหน่งของแต่ละทีมบนแผนที่คำนวณจาก กม. สะสม เทียบกับจุดอ้างอิงจริงบนถนนพหลโยธิน กรุงเทพฯ→เชียงราย:

| กม.สะสม | จุดอ้างอิง |
|---|---|
| 0 | กรุงเทพฯ (TDFB HQ) |
| 40 | ปทุมธานี |
| 80 | อยุธยา |
| 142 | สิงห์บุรี |
| 195 | ชัยนาท |
| 240 | นครสวรรค์ |
| 358 | กำแพงเพชร |
| 426 | ตาก |
| 599 | ลำปาง |
| 691 | พะเยา |
| 830 | **เชียงราย** 🏁 (เส้นชัย) |
| 890 | แม่สาย (ชายแดน) — โบนัสสำหรับทีมที่วิ่งเกิน 830 กม. |

ทีมที่วิ่งถึงจุดอ้างอิงใหม่จะได้ฉลอง (ประกาย + ป้ายลอย) บนแผนที่ และมีข่าวขึ้นในฟีดกิจกรรม ทีมที่วิ่งเกิน 830 กม. แถบความคืบหน้าจะเต็ม 100% แต่ตัวละครยังวิ่งต่อบนแผนที่ไปทางแม่สายได้ถึง 890 กม. เป็นโบนัส

**แต่ละทีม/สถานที่มีแผนที่ของตัวเอง แยกกันคนละกล่อง** — ไม่ใช่ทุกทีมแชร์แผนที่เดียวกัน จึงไม่มีปัญหาหมุด/ตัวละครซ้อนทับกันเวลาสองทีมอยู่ใกล้กัน และแต่ละกล่องมีพื้นที่เต็มสำหรับแสดงอนิเมชั่นของทีมนั้นๆ โดยเฉพาะ จัดเรียงเป็นกริดที่ยืดหด — จอกว้างเห็นหลายทีมเรียงเป็นแถว จอแคบ/มือถือจะไล่เรียงเป็นคอลัมน์เดียว

ทีม 3 ทีม: **ออฟฟิศสามย่าน**, **คลังสินค้า**, **โรงงาน** — ชื่อเหล่านี้คือสถานที่จริงของ TDFB ตรงกับตัวเลือก "สถานที่/ทีม" ในฟอร์มที่พนักงานใช้กรอกกม. เป๊ะๆ (จับคู่กันด้วยชื่อตรงตัว ไม่มี mapping table แยก)

เอฟเฟกต์/รายละเอียดเสริมในแต่ละแผนที่:
- สภาพอากาศ (ฝน/แดด/หิมะ) หมุนอัตโนมัติ + เมฆลอยผ่านเบาๆ + มีพาหนะเล็กๆ วิ่งวนไปตามถนนตลอดเวลา (แค่ตกแต่ง ไม่เกี่ยวกับระยะทางทีม)
- เส้นทางที่วิ่งผ่านแล้วเปลี่ยนเป็นสีทึบตามสีทีม พร้อมรอยฝุ่นจางๆ ตามหลังตัววิ่ง
- ป้ายอันดับ (🥇🥈🥉 หรือ #N) เทียบกับทุกทีมที่หัวการ์ด และแถว "แสตมป์" จังหวัดที่ผ่านแล้วใต้การ์ด
- ฉลองใหญ่ขึ้น (คอนเฟตตี้) ตอนถึงเชียงราย นอกเหนือจากประกาย+ป้ายลอยปกติที่ทุกจุดอ้างอิง
- ฉากมีวัด/แม่น้ำ/ต้นไม้เพิ่มเติม และมีจุดย่อยทุก 50 กม. ระหว่างจุดอ้างอิงหลักให้เห็นความคืบหน้าถี่ขึ้น
- **แถบสรุปอันดับ** ด้านบนสุด เทียบทุกทีมในที่เดียว พร้อมป้าย "สูสีกันมาก! 🔥" เมื่อ 2 ทีมห่างกันไม่เกิน 20 กม.
- **โหมดจอทีวี** (ปุ่ม 🖥️ มุมขวาบน) สลับโชว์แผนที่แต่ละทีมแบบเต็มจอทีละทีมอัตโนมัติทุก 8 วินาที เหมาะแปะจอทีวีหน้าออฟฟิศ
- **โค้งสุดท้าย** — ช่วง 50 กม. สุดท้ายก่อนถึงเชียงราย ตัววิ่งจะเรืองแสงทองพร้อมป้าย "โค้งสุดท้าย!"
- **กลางวัน/กลางคืนจริงตามเวลา** (แยกจากสภาพอากาศสุ่มปกติ) แผนที่จะมืดลงพร้อมดาวตอนกลางคืน
- **เพลงพื้นหลัง** (ปุ่ม 🔈 มุมขวาบน, ไฟล์ `public/audio/theme.mp3`) — เริ่มเล่นแบบเงียบตั้งแต่โหลดหน้า แล้ว unmute + ค่อยๆ ไล่ความดังขึ้นถึง ~18% ทันทีที่มีการคลิก/แตะ/กดคีย์ครั้งแรกในหน้า (ข้อจำกัดของเบราว์เซอร์ที่บล็อก autoplay-with-sound เสมอ) — สำหรับจอทีวี/kiosk ที่ไม่มีใครแตะจอเลย ต้องกดปุ่ม 🔈 เองครั้งแรกถึงจะมีเสียง จากนั้นจะ loop ต่อเองตลอด

## ที่มาของข้อมูล — Google Sheet

ไม่มีหน้าแอดมินให้กรอกมือ กม. สะสมของแต่ละทีมไหลมาจาก Google Sheet ทั้งหมด เป็น 3 ขั้นตอน:

1. **พนักงานกรอก Google Form** — ชื่อ, สถานที่/ทีม, วันที่วิ่ง/เดิน, ระยะทาง (กม.), แนบรูปหลักฐาน → คำตอบตกลงแท็บ Form response อัตโนมัติ
2. **แท็บ "🔒 ตรวจสอบ (ภายใน)"** — ดึงแถวจากแท็บ response มาแสดงอัตโนมัติ (สูตร `QUERY`) แล้วให้คนตรวจเทียบรูปกับกม. เลือกสถานะ "ผ่าน/รอตรวจสอบ/ไม่ผ่าน" ต่อแถว — แท็บนี้มีชื่อคน/ลิงก์รูป ห้ามเผยแพร่
3. **แท็บ "🌐 สรุปคะแนน"** — สูตร `SUMIFS`/`MAXIFS` รวมกม. เฉพาะแถวที่ "ผ่าน" แล้ว ต่อทีม (3 แถวเท่านั้น: ออฟฟิศสามย่าน/คลังสินค้า/โรงงาน) แท็บนี้ publish เป็น CSV (File → Share → Publish to web → เลือกแท็บนี้แท็บเดียว → CSV) แล้วเอาลิงก์ที่ได้ไปตั้งเป็น `SHEET_CSV_URL`

`server.js` ดึงลิงก์ CSV นั้นทุก `SHEET_POLL_MS` (default 90 วินาที) มาแปลงเป็นกม. สะสมในหน่วยความจำ — ครั้งแรกที่ server เริ่มทำงานจะรับค่ามาเงียบๆ (ไม่ยิงฟีดกิจกรรม) รอบถัดๆ ไปถ้ากม. เปลี่ยนถึงจะขึ้นฟีด "วิ่งถึง X แล้ว!" / อัปเกรดหมู่บ้านตามปกติ ชื่อทีมจับคู่กับ Sheet ด้วยข้อความตรงตัว (ออฟฟิศสามย่าน/คลังสินค้า/โรงงาน) ไม่มี mapping table แยก — ถ้าเปลี่ยนชื่อฝั่งใดฝั่งหนึ่งต้องให้ตรงกันทั้งคู่

## รันในเครื่อง

```bash
npm install
npm start
```

เปิด `http://localhost:3000/` (redirect ไป `/run-view.html` ให้เอง)

ถ้าไม่ตั้ง `SHEET_CSV_URL` จะใช้ลิงก์ CSV ที่ hardcode ไว้ใน `server.js` เป็นค่าเริ่มต้น — ตั้ง env var นี้ทับได้ถ้าเปลี่ยน Sheet ในอนาคตโดยไม่ต้องแก้โค้ด

## Deploy ให้พนักงานเข้าจากคนละเครื่องได้จริง

โปรเจกต์นี้เป็น Node.js app ธรรมดา (ไม่ใช่หน้าเว็บ static) จึงต้อง deploy ขึ้น hosting ที่รัน Node ได้ต่อเนื่อง เช่น:

### Render.com (แนะนำ ฟรีสำหรับใช้งานเบา ๆ)
1. Push โค้ดนี้ขึ้น GitHub
2. สร้าง **Web Service** ใหม่ใน Render แล้วเชื่อมกับ repo นี้
3. Build command: `npm install`, Start command: `npm start`
4. (ถ้าต้องการ) เพิ่ม Environment Variable: `SHEET_CSV_URL=<ลิงก์ CSV ของ Sheet>` — ไม่ใส่ก็ได้ถ้าใช้ Sheet เดิม
5. Deploy เสร็จจะได้ URL เช่น `https://your-app.onrender.com` — แจกลิงก์นี้ตรงๆ ให้พนักงานได้เลย (root จะ redirect ไป `/run-view.html` ให้เอง ไม่มี `/admin.html` แล้ว ไม่ต้อง mount persistent disk เพราะไม่มีการเขียนไฟล์ในเครื่องอีกต่อไป)

### Railway / Fly.io
ขั้นตอนคล้ายกัน: ตั้ง start command เป็น `npm start`, ตั้ง `SHEET_CSV_URL` ถ้าต้องการ override ไม่ต้องแนบ volume ใดๆ

## หมายเหตุด้านความปลอดภัย

- `GET /api/state` เปิดให้ทุกคนอ่านได้ (ใช้สำหรับหน้า View) — มีแค่ชื่อทีม/กม./เวลาตรวจล่าสุด ไม่มีชื่อพนักงานหรือรูปหลักฐานหลุดออกมาเลย เพราะดึงมาจากแท็บ "🌐 สรุปคะแนน" เท่านั้น (แท็บที่มีข้อมูลส่วนตัวคือ "🔒 ตรวจสอบ (ภายใน)" ไม่ได้ publish ออกเว็บ)
- ไม่มี endpoint แก้ไขข้อมูลใดๆ ในแอปนี้แล้ว (`POST /api/actions` และ `/admin.html` ถูกเอาออก) — การแก้ไขทั้งหมดทำที่ Google Sheet โดยตรง ใครมีสิทธิ์แก้ Sheet ก็แก้ข้อมูลได้ ควบคุมสิทธิ์ผ่านการแชร์ Sheet แทน
